Architecture Decision Records (ADR)

ADR-001: Service Mesh vs Direct K8s Services

Status: Accepted | Date: 2024-01-15

Context: The platform needs inter-service communication with observability and security built in.

Decision: Use plain Kubernetes Services and Prometheus annotations for scraping in the sandbox. A service mesh (Istio/Linkerd) adds overhead unsuitable for a local KinD/Minikube cluster.

Consequences: Simpler deployment; mTLS deferred to production graduation.

ADR-002: Vector Store Selection – Qdrant

Status: Accepted | Date: 2024-02-03

Context: The MCP RAG engine requires a vector store supporting hybrid search (dense + sparse).

Decision: Qdrant v1.7+ natively supports hybrid search with named vectors and payload filtering. PgVector was considered but lacks native hybrid scoring without extensions.

Consequences: Qdrant HTTP API is used from the MCP server; GRPC available for future performance improvements.

ADR-003: MCP Server Transport – Streamable HTTP

Status: Accepted | Date: 2024-03-10

Context: The Model Context Protocol server must be accessible from IDE clients (Claude Desktop, Cursor).

Decision: FastMCP with Streamable HTTP transport (SSE fallback). This maps naturally to a Kubernetes Service exposed via NodePort or port-forward.

Consequences: Clients connect to http://localhost:30808/mcp during local development.
