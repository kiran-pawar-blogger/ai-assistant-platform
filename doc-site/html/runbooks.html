Operational Runbooks

RB-001: Restart a failing pod

kubectl rollout restart deployment/<name> -n org-mind

Check pod logs: kubectl logs -f deployment/<name> -n org-mind

RB-002: Order Service 5xx spike response

  1. Open Grafana → Order Service Dashboard → check HTTP Error Rate panel.
  2. Identify the problematic route in the Skywalking UI → Trace tab.
  3. If /orders/error-demo is the culprit, it is intentional (latency injection). Set env var ERROR_DEMO_ENABLED=false to disable.
  4. Restart the deployment: kubectl rollout restart deployment/order-service -n org-mind
⚠ The /orders/error-demo endpoint is intentionally slow and returns 500. Do not page for this route.

RB-003: Qdrant collection not found

Collections are created by the MCP server init job. Re-run collection init:

kubectl exec -it deployment/mcp-server -n org-mind -- python /app/init_collections.py

RB-004: Keycloak token validation failure

  1. Verify Keycloak is healthy: kubectl get pods -n org-mind -l app=keycloak
  2. Confirm the realm exists: curl http://localhost:30080/realms/org-mind/.well-known/openid-configuration
  3. Check client secret is in sync: confirm keycloak-admin-secret matches the realm config.

RB-005: Skywalking OAP not receiving traces

  1. Confirm OAP pod is running: kubectl get pods -n org-mind -l app=skywalking-oap
  2. Check order-service env SW_AGENT_COLLECTOR_BACKEND_SERVICES points to skywalking-oap:11800.
  3. Restart order-service to re-establish the gRPC connection.

RB-006: Scale order-service under load

kubectl scale deployment/order-service --replicas=3 -n org-mind
ℹ Prometheus will auto-discover new pods via annotations. No Grafana reconfiguration needed.
